## 单个案例的最低记录项

1. 编号、标题、作者／机构、年份与来源链接。
2. 原始图片或获授权文件，以及版权／使用说明。
3. 案例类型及同时采用的数据逻辑。
4. A 数据逻辑；B 统计图形与计算；C 视觉编码；D 信息架构；E 视觉叙事架构。
5. 证据、局限、反例和分析日期。
6. 可归纳原则及应回写到文件夹 01 的链接。

## 图片与链接规则

- 图片只保存在本目录或其子目录，不复制到文件夹 01。
- 文件夹 01 只用相对 Markdown 链接指向案例。
- 未确认来源或版权的图片先记录外部链接，不擅自重新发布。

## 更新流程

新增案例 → 逐案分析 → 同类比较 → 提炼原则 → 更新文件夹 01 → 检查双向链接。结论必须能回到课件页码或案例证据。

## 统一评价口径

- 选题：可视化形式要匹配内容特点和读者背景；专业程度可随读者知识提高。
- 设计流程：数据收集与清洗 → 数据集与结构搭建 → 视觉编码与版式排布 → 数据关联与内容呈现。
- 动态评价：用“测试轮盘”在抽象／模拟、复杂／简单、创新／熟悉、装饰／实用等维度寻找平衡。
- 质量目标：清晰、准确、有效，让读者用更少时间获得更多信息。
- 风险控制：控制数据／油墨比，避免图表垃圾；形式应帮助理解，而不是遮蔽数据。
